## Project Overview

A German-language family recipe collection built with [VitePress](https://vitepress.dev). Recipes are Markdown files; the site is a static PWA deployed to GitHub Pages at `https://yvo-niedrich.github.io/family-recipes/`. It works offline: all pages and the search index are precached, recipe photos are cached once viewed.

## Key Commands

```bash
npm run dev       # Dev server with hot reload
npm run build     # Production build → docs/.vitepress/dist
npm run preview   # Serve the production build (restart it after every rebuild — it caches the file list)
npm test          # Vitest: search term processing + checks on every recipe file
```

There is no separate index step: search index, category/tag pages and recipe dates are all generated by `vitepress build`.

## Adding a New Recipe

### 1. Create the Markdown File

Create a `.md` file directly in `docs/recipes/` (no subdirectories). The file name becomes the URL (`/recipes/<file-name>`), so use lowercase with underscores:

```
docs/recipes/kartoffel_suppe.md
```

### 2. Add YAML Frontmatter

```yaml
---
name: Recipe Name
categories: Category1, Category2
preview: /images/recipe-image.jpg
tags: tag1, tag2, tag3

---
```

- `name` (required): Display name. **Quote it if it contains a colon**: `name: "Hühnersuppe: Die hilft bei Erkältung"` — otherwise the YAML is invalid and the build fails.
- `categories` (required): Comma-separated. Existing categories: `Frühstück`, `Vorspeise`, `Hauptgericht`, `Beilage`, `Salat`, `Snacks`, `Dessert`, `Kuchen`, `Getränk`, `Sonstige`. A new category automatically gets its own page and sidebar entry (sidebar order is defined in `CATEGORY_ORDER` in `docs/.vitepress/recipes.ts`).
- `preview` (optional): Path to a photo in `docs/public/images/`, e.g. `/images/soup.jpg`. Case-sensitive (GitHub Pages is). Leave empty (`preview:`) if there's no photo; a placeholder is shown.
- `tags` (optional): Comma-separated, lowercase (e.g. `vegetarisch, vegan, thermomix`). Each tag gets a page under `/tag/`.

### 3. Write the Recipe Content

```markdown
# Recipe Name

## Zutaten

- 500 g Ingredient 1
- 1 TL Ingredient 2

## Zubereitung

1. First step.
2. Second step.
```

The `# Recipe Name` heading should match `name`.

### 4. Add a Photo (Optional)

Put the image in `docs/public/images/` (lowercase file name, JPG, ideally ≤ 300 KB) and reference it in `preview:`.

### 5. Verify

Run `npm test` — it fails on invalid frontmatter, missing categories, non-lowercase file names, or a `preview` that doesn't exist.

## Architecture

```
docs/
  recipes/*.md               Recipe content
  public/images/             Recipe photos (cached on view, not precached)
  public/placeholder/        Placeholders for recipes without photo (precached)
  index.md, alle.md, ...     Overview pages using the components below
  kategorie/[category].md    Dynamic route: one page per category (+ .paths.ts)
  tag/[tag].md               Dynamic route: one page per tag (+ .paths.ts)
  .vitepress/
    config.mts               Site config: sidebar, search, PWA, German UI labels
    recipes.ts               Build-time registry: frontmatter + dates from git (Node only)
    recipes.data.ts          Data loader exposing the registry to the client
    search.ts                MiniSearch processTerm (German stemmer, stopwords)
    theme/                   Default theme + RecipeGrid, RecipeHeader, CategoryChips, TagCloud
tests/                       Vitest tests
```

### Search

VitePress local search (MiniSearch), fully client-side and offline. `processTerm` in `docs/.vitepress/search.ts` normalizes umlauts, drops stopwords/recipe boilerplate (`Zutaten`, `Stufe`, …) and applies a simple German stemmer. Query words are combined with AND.

**Critical:** VitePress sends `processTerm` to the browser via `toString()`. It must stay fully self-contained — no imports, no references to module-level variables. `tests/search.test.ts` checks the round-trip. Ingredients must not be added to the stopword list, or they become unsearchable.

### Recipe Dates

`recipes.ts` derives each recipe's `added` (home page "Neu hinzugefügt") and `updated` ("Zuletzt geändert") dates from a single `git log` walk:
- Renames are followed and pure renames (R100) don't count as edits.
- Commits listed in `.git-blame-ignore-revs` don't count as edits. Add bulk formatting commits there.
- CI must check out with `fetch-depth: 0` (already set in the workflow).

### Offline / PWA

`@vite-pwa/vitepress` (Workbox `generateSW`, `autoUpdate`). Precache: HTML, JS, CSS, icons, placeholders. Runtime `CacheFirst` for `/images/`. Offline, uncached photos fall back to placeholders (grids) or are hidden (recipe header).

Keep per-page HTML small — it's precached for every page. That's why the sidebar lists only categories (listing all recipes made each page ~120 KB) and `metaChunk: true` is set.

## Deployment

`.github/workflows/deploy.yml` runs tests, builds and deploys to GitHub Pages on push to `main`. Repository settings → Pages → Source must be "GitHub Actions". `base` in `config.mts` must match the repository name (`/family-recipes/`).
