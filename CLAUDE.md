# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project Overview

A German-language family recipe collection built with [VitePress](https://vitepress.dev). Recipes are Markdown files; the site is a static PWA deployed to GitHub Pages at `https://yvo-niedrich.github.io/family-recipes/`. It works offline: all pages and the search index are precached, recipe photos are cached once viewed.

## Key Commands

```bash
npm run dev       # Dev server with hot reload
npm run build     # Production build → docs/.vitepress/dist
npm run preview   # Serve the production build (restart it after every rebuild — it caches the file list)
npm test          # Vitest: search term processing + checks on every recipe file
```

There is no separate index step: search index, category/tag pages and recipe dates are all generated by `vitepress build`.

## Adding a New Recipe

### 1. Create the Markdown File

Create a `.md` file directly in `docs/recipes/` (no subdirectories). The file name becomes the URL (`/recipes/<file-name>`), so use lowercase with underscores:

```
docs/recipes/kartoffel_suppe.md
```

### 2. Add YAML Frontmatter

```yaml
---
name: Recipe Name
categories: Category1, Category2
preview: /images/recipe-image.jpg
tags: tag1, tag2, tag3

---
```

- `name` (required): Display name. **Quote it if it contains a colon**: `name: "Hühnersuppe: Die hilft bei Erkältung"` — otherwise the YAML is invalid and the build fails.
- `categories` (required): Comma-separated, one or more of: `Frühstück`, `Vorspeisen & Snacks`, `Suppen & Eintöpfe`, `Salate`, `Hauptgerichte`, `Beilagen`, `Soßen & Grundrezepte`, `Desserts`, `Kuchen & Gebäck`, `Getränke`. These are the only allowed values (`CATEGORIES` in `docs/.vitepress/recipes.ts`, checked by `npm test`); category names must never contain a comma. Conventions: Marmeladen, Aufstriche and bread go to `Frühstück` (bread also gets the `brot` tag); soups and stews go to `Suppen & Eintöpfe`, not `Hauptgerichte`; sauces, dips, doughs and other base recipes go to `Soßen & Grundrezepte`.
- `preview` (optional): Path to a photo in `docs/public/images/`, e.g. `/images/soup.jpg`. Case-sensitive (GitHub Pages is). Leave empty (`preview:`) if there's no photo; a placeholder is shown.
- `tags` (optional): Comma-separated, lowercase (e.g. `vegetarisch, vegan, thermomix`). Each tag gets a page under `/tag/`.

### 3. Write the Recipe Content

```markdown
# Recipe Name

## Zutaten

- 500 g Ingredient 1
- 1 TL Ingredient 2

## Zubereitung

1. First step.
2. Second step.
```

The `# Recipe Name` heading should match `name`.

**Notes** use GitHub alert syntax with an explicit German title (VitePress 1.x can't translate the default labels). The type decides the styling:

```markdown
> [!TIP] Tipp
> Statt Mandeln gehen auch Cashewkerne.

> [!TIP] Variante: mit Öl
> ...

> [!NOTE] Anmerkung
> Background info, comments, "Warum …", storage notes.

> [!WARNING] Achtung
> Safety hints (hot liquids etc.).

> [!IMPORTANT] Nährwerte pro Portion
> - 340 kcal
> - 25 g Fett
> - 13 g KH

> [!INFO] Quelle
> [chefkoch.de](https://www.chefkoch.de/...)
```

- `[!IMPORTANT]` is reserved for **Nährwerte**: one list item per value, rendered as pills.
- `[!INFO]` is reserved for **Quelle**: rendered as a compact one-line footer.
- Don't use `[!CAUTION]`/`[!DANGER]`, and don't write notes as `> **Tipp**` (renders as a plain quote). `npm test` checks both.

**Thermomix settings** in steps are wrapped in a badge:

```markdown
2. Zwiebel zugeben und <Badge type="tip">3 Sek./Stufe 5</Badge> zerkleinern.
```

Only the setting goes inside the badge (time/temperature/direction/speed), not the surrounding instruction.

### 4. Add a Photo (Optional)

Put the image in `docs/public/images/` (lowercase file name, JPG, ideally ≤ 300 KB) and reference it in `preview:`.

### 5. Verify

Run `npm test` — it fails on invalid frontmatter, missing categories, non-lowercase file names, or a `preview` that doesn't exist.

## Architecture

```
docs/
  recipes/*.md               Recipe content
  public/images/             Recipe photos (cached on view, not precached)
  public/placeholder/        Placeholders for recipes without photo (precached)
  index.md, alle.md, ...     Overview pages using the components below
  kategorie/[category].md    Dynamic route: one page per category (+ .paths.ts)
  tag/[tag].md               Dynamic route: one page per tag (+ .paths.ts)
  .vitepress/
    config.mts               Site config: sidebar, search, PWA, German UI labels
    recipes.ts               Build-time registry: frontmatter + dates from git (Node only)
    recipes.data.ts          Data loader exposing the registry to the client
    search.ts                MiniSearch processTerm (German stemmer, stopwords)
    theme/                   Default theme + Catppuccin + RecipeGrid, RecipeHeader, RecipeTools, CategoryChips, TagCloud
tests/                       Vitest tests
```

### Theme

Default VitePress theme with the [Catppuccin](https://github.com/catppuccin/vitepress) palette (`@catppuccin/vitepress`, Latte for light mode, Macchiato with the default mauve accent for dark mode), imported in `theme/index.ts`. Alert/badge/checklist styling is in `theme/custom.css`. The app icon and PWA `themeColor` are deliberately Latte **peach** (`#fe640b`), not the accent.

### Home Page & Mobile Layout

- The home page (`docs/index.md`) shows `<RecentRecipes />` ("Zuletzt angesehen", up to 6 recently viewed recipes from `localStorage` key `recent-recipes`, written by `RecipeHeader.vue`; renders nothing until at least one recipe was viewed; a "Leeren" button in its heading clears the history), then "Neu hinzugefügt". Heading buttons like this and the ingredient "zurücksetzen" share the `heading-with-action` / `heading-action` styles in `theme/custom.css`.
- Below 960px the VitePress "Menü / Auf dieser Seite" bar is hidden; navigation goes through the hamburger menu.
- Below 768px the header is taller (72px), the site name is hidden (logo stays) and search is a wide "Rezepte suchen" field. All in `theme/custom.css`.

### Recipe Tools (`RecipeTools.vue`)

Enhances the rendered recipe HTML (no Markdown changes needed):
Every list item under a `Zutaten` heading (h2 or h3, up to the next heading of the same level) becomes a tappable checkbox for shopping. State is stored per recipe in `localStorage` (`recipe-checked:<slug>`). Once something is checked, a "X von Y abgehakt · zurücksetzen" button appears inside the first `Zutaten` heading (right-aligned, wrapping below the title on narrow screens).

### Search

VitePress local search (MiniSearch), fully client-side and offline. `processTerm` in `docs/.vitepress/search.ts` normalizes umlauts, drops stopwords/recipe boilerplate (`Zutaten`, `Stufe`, …) and applies a simple German stemmer. Query words are combined with AND. Each page is indexed as a single entry (`splitIntoPage` via `_splitIntoSections`), so results list each recipe once and link to the page rather than to a section anchor; this also lets query words match across Zutaten and Zubereitung. VitePress shows at most 16 results (hard-coded in its search box).

**Critical:** VitePress sends `processTerm` to the browser via `toString()`. It must stay fully self-contained — no imports, no references to module-level variables. `tests/search.test.ts` checks the round-trip. Ingredients must not be added to the stopword list, or they become unsearchable.

### Recipe Dates

`recipes.ts` derives each recipe's `added` (home page "Neu hinzugefügt") and `updated` ("Zuletzt geändert") dates from a single `git log` walk:
- Renames are followed and pure renames (R100) don't count as edits.
- Commits listed in `.git-blame-ignore-revs` don't count as edits. Add bulk formatting commits there.
- CI must check out with `fetch-depth: 0` (already set in the workflow).

### Offline / PWA

`@vite-pwa/vitepress` (Workbox `generateSW`, `autoUpdate`). Precache: HTML, JS, CSS, icons, placeholders. Runtime `CacheFirst` for `/images/`. Offline, uncached photos fall back to placeholders (grids) or are hidden (recipe header).

Keep per-page HTML small — it's precached for every page. That's why the sidebar lists only categories (listing all recipes made each page ~120 KB) and `metaChunk: true` is set.

## Deployment

`.github/workflows/deploy.yml` runs tests, builds and deploys to GitHub Pages on push to `main`. Repository settings → Pages → Source must be "GitHub Actions". `base` in `config.mts` must match the repository name (`/family-recipes/`).
